# Reporting and portability

Report requests are bound to the authenticated organization and current membership. Optional tournament assignments restrict every row and export. Report types are `summary`, `matches`, `standings`, `team_performance`, `schedule`, `court_use`, `referees`, `outstanding_results`, `audit`, and `history`. Public reporting is explicitly opt-in per tournament's `display.public_reports`; private contacts, raw audit payloads, credentials and internal session metadata are excluded.

Filters: `tournament_id`, `division_id`, `stage_id`, `team_id` (entry or reusable team), `venue_id`, `court_id`, `status`, `result_status`, `outcome`, `from`, `to`, and `search`. Date bounds are inclusive ISO calendar dates or ISO instants in the tournament/organization timezone. Sorting uses known output columns; `direction=asc|desc`; `columns` is a comma-separated subset of known columns. Interactive results are bounded by `page` and `page_size` (at most 200). Direct downloads use persisted, filtered source data with a bounded ceiling; request a queued export for larger data. Metadata carries organization, tournament, timezone, filters, generation timestamp, official/provisional status and source match/result generations. Report views do not grant permission.

CSV files use UTF-8 and spreadsheet formula escaping. XLSX files contain values and metadata without executable user formulas; metadata longer than a spreadsheet cell is split into labeled, ordered parts without truncation. PDFs contain escaped text, metadata, repeated table headers and the application credit. Match rows identify their source version; standings PDFs include the configured ranking policies/explanations. Successful export means a durable private file was written and job state committed; download authorization remains required. Filenames are generated from internal job UUIDs, never user-controlled paths. Jobs expire; membership revocation blocks generation and download even when a file exists. Private storage must be durable and nonpublic in production.

Wide PDF tables repeat a selected stable entry/match/assignment/audit/tournament ID across column groups; a selection excluding IDs uses consistent Row numbering to link the pages. Embedded Noto Sans fonts cover the tested extended Latin, Greek and Cyrillic text; a PDF Symbol fallback preserves the infinity ranking value. Font licenses/source checksums are in `volleyball/fonts/`. The [synthetic PDF review](report-pdf-review.md) records all-page visual checks and fixes; universal script shaping, printers and mobile PDF readers remain unverified.

CSV templates cover reusable teams, event entries, manually reviewed fixtures and referee display metadata. Preview validates headers, required fields, duplicate identifiers, allowed values, references and aware dates; commit reruns validation in one transaction. Rows with errors prevent the entire import. Fixtures cannot overwrite running or finalized results, and metadata imports do not create referee accounts. Preview and errors remain in a persisted private job, with the import audited at commit. CSV imports accept UTF-8, bounded files/rows, and reject malformed headers; arbitrary spreadsheets/macros are not accepted.

The administrator business-data JSON export includes only scoped organization/configuration, teams, venues/courts, competitions, entries, accepted scoring/result history, announcements and source metadata. It excludes credential hashes, MFA/reset/session/grant secrets, private infrastructure recovery material and other organizations. It is for ownership/portability. Selective recovery and disaster recovery are separately described in `operations-runbook.md`.

Scheduled distribution and custom report builders are deferred. Export jobs can be queued and polled with the V1 worker. Weather is independent: without configured licensed adapter output is explicitly unavailable, and provider failure cannot block reports/scoring.
